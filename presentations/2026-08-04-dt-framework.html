Architecture — concepts and stack

  • Capability: typed input → output contract (e.g. diagnostics → equilibrium). A digital twin is a graph of capabilities, not of models.
  • Model investigator: one architecture × capability — learner loop + inference task + callbacks.
  • Science agent: all investigators of one capability + a cross-model learner which publishes the model selector (what model to serve, now).
  • Two concurrent flows, coupled by pub/sub: learning (until objective, restarts on new data) ∥ inference (forever, hot-swaps models).

Features

  • Multi-architecture learning per capability, with inference-time model selection and hot-swap serving.
  • Event-driven: any trigger kind — sensor, user, timer, sim, service; learning restarts on callbacks, criteria are pluggable (metrics, cost, UQ, human/agent).
  • Transport-agnostic pub/sub: abstract frontend, adapters for ORBIT / Redis / MQTT / in-process; references on the channel, bulk data out of band.
  • DT-as-a-service: one ORBIT broker hosts many twins (session per twin, worker process each); the client is a console — attach, tweak, detach, the twin keeps running.
  • Composition: capabilities chain into graphs (SPLIT / AGGREGATE); pre-existing sims wrap as fixed-model nodes.
